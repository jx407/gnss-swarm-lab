## ② 方法

### 静态与 DOM 检查

使用 Playwright 打开 `file://` 页面，等待 `GLAPP` 启动后执行：

- `document.querySelectorAll` 统计 10 个 tab、10 个 tabpanel、26 个 range、19 个 select、19 个 button、26 个 canvas。
- 检查 `role`、`aria-selected`、`aria-controls`、`aria-labelledby`、`hidden`、`tabindex`。
- 对 range/select/button 读取 `el.labels`、`aria-label`、`aria-labelledby`、可见文字和 `el.value`。
- 对 slider 读取 `aria-valuetext`，并检查其 `id + '-val'` 伴随值是否存在。

### 键盘实测

- 从页面顶部连续按 `Tab`，记录 `document.activeElement`。
- 对 tab 聚焦后依次按 `ArrowRight`、`ArrowDown`、`ArrowLeft`、`ArrowUp`、`Home`、`End`。
- 在 10 个面板逐一激活后，从顶部依次按 `Tab`，检查该面板当前可见的每个 `input/select/button/summary/[tabindex]` 是否被实际走过。
- 单独运行 `top-tab-probe.js`，确认顶部 `<details><summary>` 和 tablist 的初始 Tab 顺序。

### 对比度计算

从浏览器实际 `getComputedStyle` 取值，并按祖先透明背景做合成，然后按 WCAG 2.1 计算：

```text
C_srgb = C8 / 255
C_lin = C_srgb <= 0.03928
        ? C_srgb / 12.92
        : ((C_srgb + 0.055) / 1.055) ^ 2.4
L = 0.2126 R_lin + 0.7152 G_lin + 0.0722 B_lin
contrast = (max(L1, L2) + 0.05) / (min(L1, L2) + 0.05)
```

例：`.text-muted` 的 `#5a5f6a` 对白底：`Lfg = 0.113987`，`Lbg = 1.000000`，比值为 `(1.000000 + 0.05) / (0.113987 + 0.05) = 6.403:1`。完整数值见 `metrics.json` 的 `colors.light` / `colors.dark`。

## ④ 确认问题清单与严重度

### 总计数

- **P0：0**
- **P1：0**
- **P2：3**
  - **P2-1**：10 个 tab 全部是默认 Tab stop；未选 tab 应为 `tabindex="-1"`，否则键盘用户要额外经过 9 个 tab。证据：`tabindex=null ×10`，Tab 序列 `gl-tab-ca...gl-tab-pll`。
  - **P2-2**：页面没有 `main` / `nav` landmark；`#gnss-lab` 只是普通 `div`，tablist 也只是 `div role=tablist`。证据：`aria.landmarks=[]`。
  - **P2-3**：26/26 个 range 缺 `aria-valuetext`；虽然 26/26 都有可见伴随值，但辅助技术得到的主要是数值而非带单位的完整文本值。证据：`ariaValueTextMissingRange=26`，`visibleValueMissingRange=0`。

### 对比度部分没有计入上述 3 条的内容

- 文本样本没有 `<4.5:1`。
- 当前实际 `.form-select` / `.btn` 边框没有 `<3:1` 的有效问题（6.403:1 / 7.789:1）。
- `--border` 原始 token（`#d8dbe0` / `#383d47`）对页面背景为 `1.388:1` / `1.645:1`，以及主按钮边框相对自身填充色为 `1.408:1` / `1.047:1`；它们被列为残余风险，但当前分别由 line 851 覆盖、或由填充色承担图形辨识，因此没有单独计为确认失败。

## ⑤ 未验证边界

1. **未使用真实屏幕阅读器**：本报告测试的是 Chromium DOM/Playwright 可读名字与键盘行为，没有运行 NVDA、JAWS、VoiceOver，也没有做完整 Accessibility Tree 的逐节点人工宣读。
2. **未覆盖全部浏览器**：只测了指定运行时的 Chromium 151；Firefox/Safari 未验证。
3. **未做颜色盲/低视力用户访谈**：对比度是公式计算，不是主观可用性测试；色觉模拟也未做。
4. **未做屏幕缩放到 200%/400% 的重排测试**：只测了 `1280 × 900` 和指定 light/dark 色彩方案。
5. **slider 的完整 AX 值没有单独 dump**：`aria-valuetext` 缺失是 DOM 实测；原生 range 数值语义由浏览器实现承担，未独立输出完整 AX tree。
6. **tab roving tabindex 是按 ARIA APG 的改进项，不是已验证的阻断性失败**：当前方向键、焦点和 selected/hidden 同步都工作。
7. **landmark 影响依赖读屏器导航快捷键**：Chromium DOM 中没有 `main/nav`，但没有对具体读屏器的 landmark 跳转做端到端验证。
8. **次生问题未覆盖**：没有做表单提交、自动播放、动画减少偏好、错误提示关联等超出本任务范围的检查。
