### P0-1　标签页数量与需求不符：需求 13，实际 10

- **证据**：全部 10 组组合 `[role=tab]` 计数 **= 10**（1600/1280/980/760/420 × light/dark 一致）；
  快照 `de6858a3…` 静态扫描 `role="tab"` = 10、`gl-panel-*` = 10。截图 `1600-light-nav-top.png`。
  实际 10 个标签：星座几何、C/A 码、捕获搜索、定位解算、多径与遮挡、RAIM 检核、全球几何、误差预算、冷启动、载波跟踪。
- **口径说明（已核）**：DLL 跟踪环对比图在**冷启动面板末**（`#gl-dll-canvas`）、
  Hatch 载波平滑码在**载波跟踪面板下半**（`#gl-hatch-canvas`）、
  双频消电离层在**定位解算 / 误差预算面板内**。三者是"面板内子块"，不是独立标签页。
- **建议**：与需求方确认"13"是否把 3 个子块也算作"页"；若要求 13 个独立标签页，需新增 3 个 tab
  （并把现有子块抽成面板），nav 超过 10 项时建议同时给出分组或二级导航。

### P0-2　冷启动面板末尾的 DLL 对比图默认是 780 px 空白块

  点击 `#gl-dll-run` 后变为 1560×230、22171 px 已绘制。
  **定向取证截图**（因为批量截图是 900 px 视口、拍不到面板中部这一块，故单独补拍）：

### P1-3　420 宽下冷启动控件 11 行单列，面板 2557 px

### P1-4　长"读法"说明在 420 下仍整段展开（最长 435 字）

### P1-5　导航不吸顶 + 全站无标题层级，长滚动后失去上下文

- **证据**：420 宽导航折成 **3 行 / 107 px**，且 CSS 中**无 `position: sticky/fixed`**
  （快照全量扫描 0 命中）；整页 **0 个 `<h1>/<h2>/<header>`**（0 命中），面板自身也没有可见标题。

- **建议**：`.nav` 加 `position: sticky; top: 0` + 背景色；每个面板顶部加一个 `<h2>`（用标签名）；
  若面板内再分子块（如载波跟踪里的 Hatch），给子块加 `<h2>/<h3>`。

### P2-6　控件分组只覆盖了 1 个面板（10 个中的 1 个）

- **证据**：快照中 `class="gl-group"` 共 **4 个**、`gl-legend` 4 个，**全部在 `gl-panel-cold`**：
  "① 场景"、"② 接收机前端"、"③ 电离层"、"④ 算法与执行"（1600 宽下 5r/11f，420 宽下 11r/11f）。
  其余 9 个面板共 40+ 个控件没有任何分组标题。
- **建议**：把冷启动已验证有效的 `.gl-group/.gl-legend` 推广到 sky（来源/位置/掩膜）、
  pos（噪声/系统/电离层）、atm（模型参数/预设）、pll（环路/鉴别器/数据位），改造成本低（样式已有）。

### P2-7　深浅两主题的控件描边与卡片分界对比度不足

- **证据**：`--border` vs 页面底 light **1.39:1** / dark **1.64:1**（建议 ≥3:1）；
  卡片面 vs 页面底 light **1.09:1** / dark **1.15:1**。文字对比度全部达标（0 处不合格）。
- **建议**：把 `--border` 提到约 3:1（light 约 `#767b85`，dark 约 `#6b7280`），
  或给 `select`/次要按钮改用两档描边（外浅内深）；卡片可加一层极浅描边而非只靠底色差。

### P2-8　移动端触控目标偏小

- **证据**：420 宽实测 `input[type=range]` 高 **16 px**、`input[type=checkbox]` **13×13 px**
  （阈值为 WCAG 2.5.8 的 24×24）；`select` 30 px 达标。
- **建议**：`@media (max-width:620px)` 下把 range 的可点区域用 `padding` / `height` 提到 ≥24 px，
  checkbox 用 `transform: scale(1.6)` 或自定义 24 px 控件（同时能解决 dark 下原生控件风格不统一）。

### P2-9　主题只能跟随系统，页内无法切换

- **证据**：快照中无任何 theme/toggle 控件 id（扫描 0 命中），配色仅由 `@media (prefers-color-scheme: dark)` 驱动；
  light/dark 由 Playwright 的 `colorScheme` 模拟得到（截图 `*-light-*` / `*-dark-*`）。
- **建议**：若要"两种主题都能看"，加一个跟随系统/亮/暗三态切换（`data-theme` + 变量覆盖即可，现有变量已集中在 `:root`）。

## 5. 不能确认 / 未验证的部分（如实列出）

1. **"13 个标签页"的原始口径**未拿到：本报告只能确认成品页是 **10 个 tab**，以及 3 个模块以面板内子块存在；
   无法判定这是"需求写错"还是"实现缺 3 个页面"。
2. **成品页仍在被并发修改**：本次审计后（23:19:03 之后）若又重建，结论需要重跑；
   本报告只对 md5 `de6858a3e53b697cfdd18aa2ca652d37` 负责。
3. **重叠判定的方法学误差**：扫描脚本的"两两相交"会把**行内元素的包围盒**误当重叠
   （一个跨行折行的 `<b>`，其 union 矩形会覆盖同行其它行内元素），也会被**闭合 `<details>` 内仍保留布局盒子**的
   内容干扰。已用两轮定向复核修正：改用 `checkVisibility()` 过滤折叠内容 + 只对**块级直接子元素**做相交判定，
   得到"真实可见重叠 = 0"。因此 §2.1 里"原始计数 10 处"只作为方法学记录，**不作为缺陷**。
4. **未做真实指针手势**：滑块是派发 `input`/`change` 事件（等价于拖动后的值变化），不是真实的 pointer 拖拽轨迹；
   "拖动过程中"的表现（防抖 350 ms 的重算是否卡顿）未逐帧验证。
5. **未在非 Chromium 内核验证**：仅 Playwright Chromium（headless）。Safari / Firefox / 移动端真机未测，
   尤其 `<details>` 折叠内容、原生 `select` / `checkbox` 与 `accent-color` 的差异未覆盖。
6. **未做屏幕阅读器 / 键盘全流程**：只做了静态检查（`role=tab`、`aria-controls`、`aria-selected`、
   `canvas` 有 `role="img"` + `aria-label`）；未验证 Tab 键顺序、焦点可见性、读屏朗读顺序。
   注意：现有 tab 实现是"按钮 + hidden 面板"，**未实现方向键切换 tab 的 WAI-ARIA tabs 键盘交互**（此项为静态推断，未做键盘实测）。
7. **未验证数值正确性**：本次只审 UI/UX（版式、可读性、可用性），不判断各面板物理量的计算是否正确。
8. **未做长时间/高频交互压力测试**：每页只交互 1 次；未测连续拖动的 CPU/内存占用。
9. **高对比度模式（forced-colors）**未验证。
