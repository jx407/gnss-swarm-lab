# 契约增补 v7（2026-10-06）——修订 §13 时间口径（**取代 CONTRACT-v6.md §13 第 5 步**）

阅读顺序：本文件 + `CONTRACT.md` §0 + v6 §13 的其余部分。**不得修改** `allSats`/`multiconst`/其它既有函数。

## §13-rev 时间口径修订（原因：v6 口径物理不自洽，判据第 6 项无法满足）

v6 §13 有两个互相矛盾的要求：
- 正文说"θ 由**该星历元** UTC 时刻算"，且 `relSec` 相对各星自身历元；
- 判据 `tests/test-realconst.js` 第 68–70 行却用 `gmstFromUnix(0)` 反旋比对。

两种写法都不对，实测（`review/probe-realconst-timebase.js`）：

| 口径 | 上海可见星 | PDOP | 问题 |
|---|---|---|---|
| 每星各用自身历元的 θ | **17 颗** | 1.64 | 同一时刻被"糊"成不同时刻的星座，17 颗是假象 |
| θ = gmstFromUnix(0)（1970 起算） | 9 颗 | 3.68 | 整星座被随机旋转，与"上海真实天空"无关 |
| **统一参考时刻 T0** | 9 颗 | 1.65 | 物理自洽，24 h 内 7–11 颗 / PDOP 1.38–2.54 ✅ |

**修订后的权威定义**：

```js
GNSS.realConst(relSec, opts) -> [ { prn, norad, sys:'G', x, y, z, aM, e, iDeg, periodS } ]
GNSS.realConst.T0  // number：REAL_GPS_ELEMENTS 中 epoch 的最大 Unix 秒（导出常数，便于测试独立核对）
```

- `tRef = (opts && Number.isFinite(opts.refUnix)) ? opts.refUnix : GNSS.realConst.T0`
- 每颗卫星 `Δt = (tRef + relSec) − epochUnix(该星)`（**相对自身历元**，可正可负）
- `θ = GNSS.gmstFromUnix(tRef + relSec)`（弧度，**统一参考时刻**，不是逐星历元）
- `ECEF = Rz(−θ) · ECI(Δt)`，其余传播步骤（牛顿迭代、ν/r、Rz(Ω)·Rx(i)·Rz(ω)）与 v6 §13 完全相同
- `gmstFromUnix(unixSec)`：`θ = (280.46061837 + 360.98564736629·(JD − 2451545))`，`JD = unixSec/86400 + 2440587.5`，返回**弧度**（未归一到 [0,2π) 也可以，测试只比较 mod 2π）
- 非法 `relSec`（非有限数）→ `[]`；`REAL_GPS_ELEMENTS` 缺失/空 → `[]`；一律不抛异常；纯函数、不改入参

### 数据已知局限（页面必须如实标注，不允许写成"精密星历"）
- 元素是 **TLE 平均根数**，本模块只做**简化开普勒传播**（无 SGP4、无 J2 长期项、无大气/光压）。
- 32 颗的历元跨度 18.62 天；其中 **28 颗距 T0 ≤ 2 天**、2 颗 2–4 天、1 颗 ~15 天、1 颗 18.6 天。
- 未建模的 J2 长期项（升交点西漂 ≈ −0.039°/天、近地点幅角漂移等）实测影响（`review/probe-j2-error.js`，
  做法：同一套根数分别用"纯开普勒"与"加 J2 长期项"传播到 T0，比较位置差）：新鲜 28 颗（外推龄 ≤2 天）
  **中位 4.2 km、最大 22 km**；最老 1 颗 PRN21（18.62 天）**151 km**，PRN13（14.64 天）69 km。
  （注：**不能**用"r·ΔΩ"这种一阶估计替代实测——RAAN 偏差造成的实际位移与卫星在轨道上的位置有关，
  在升交点附近位移为零；一阶估计给 PRN21 约 336 km，实测 151 km。）
- 结论：本模块给出的是"**几何结构可信、公里级误差**的真实星座样本"，不是精密星历。
