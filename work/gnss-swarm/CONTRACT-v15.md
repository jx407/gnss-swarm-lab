# 契约增补 v15（2026-10-06）——§16.4 载波环的推荐使用范式（增益调度）

模块 `winners/pll.js` 本身不变（`pllTrack` 的 α、β、disc 由调用方给）。本文件规定**在冷启动/跟踪链路里怎么用**，
因为直接拿标准增益去跟踪会踩两个坑（都有实测证据）：

## 两个坑
1. **更新率**：历元间隔 0.1 s 时，若一个历元只喂 1 个 4 ms 块，环路每历元要吸收 `2π·f_d·0.1`
   （GPS L1、f_d≈4200 Hz → 约 2640 rad），而二阶环每次更新只能动 ~α·|d| ≈ 0.2 rad →
   实测本振相位误差 2.8–3.1 rad（**根本没跟住**）。
   修法：**一个历元内拆成 25 个连续 4 ms 细块**（`FINE_M=25`、`FINE_DT=0.004`；细块的载波初相按
   `2π·f_dop·Δt` 逐块累积，且**本历元起点相位要在累加之前取**——顺序写反会让细块相位超前一个历元）。
2. **牵引范围**：Costas 的 `|d| = |0.5·sin2Δφ| ≤ 0.5`，4 ms 更新下牵引范围只有 ~8 Hz；
   而该工程的 `acquire` **不做多普勒插值**（峰值只落在网格上，实测 250 Hz 网格误差可达 83 Hz）→ 牵不进去。
   修法：捕获网格收到 **100 Hz**（实测残差 ≤46 Hz），并用**宽牵引的 atan 鉴相牵入**（±50 Hz）。

## 推荐范式（与 app/80-coldstart.js 一致）
```
pass1 = pllTrack(epochs, { fNco0: 捕获多普勒, disc: 'atan', alpha: 0.8, beta: 0.08 })   // 高增益宽牵引
if (!pass1.locked) {
    Δf = median(pass1.freq 末段)          // 中位数：抗半周滑失
    pass2 = pllTrack(epochs, { fNco0: 捕获多普勒 + Δf, disc: 'costas', alpha: 0.4, beta: 0.02 })
    取 lockQual 更高的一次作为输出
}
```
- 锁住就直接用 pass1：对着 Hatch 只有**相位增量**有用，高增益的相位抖动折算到距离是亚厘米级（<< 码噪声 30 m）。
- 第二遍按需执行 → 既提高可靠性又省时间（实测整链从 6.5 s 降到 3.9 s）。

## 实测效果（浏览器 `qa/check21.js` + 逐星诊断 `qa/probe-pll-perstar.js`）
| 方案 | 牵入率 | lockQual | max\|相位误差\| |
|---|---|---|---|
| 单遍标准增益（0.4/0.02，Costas） | 2/6 | 0.585 | 3.14 rad |
| 细块 + 单遍 atan（0.4/0.02） | 5/6 | 0.998 | 2.83 rad（失败星滑失） |
| **细块 + 增益调度（本范式）** | **6/6** | 0.9956–0.9974 | **0.088–0.670 rad** |
对应精度阶梯：原始码 58.8 m → 载波平滑 26.1 m → 导航滤波 23.5 m。
