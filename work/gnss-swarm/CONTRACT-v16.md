# 契约增补 v16（2026-10-06）——§16.5 `freq` 的混叠语义与 ±125 Hz 边界（ds4.1 子代理发现 + 主代理复核）

## 事实（判据已锁定，`tests/test-pll.js`）
细块的相干积分长度 T=4 ms ⇒ 每块的相位推进是 `2π·f·T`，而鉴相器只能观测 **mod 2π**，
所以"块到块的相位推进"存在 **1/T = 250 Hz** 的模糊：
- `pllTrack` 的 `freq[]` 输出是**混叠后的绝对多普勒** `wrap_{±125}(f_true) + 250k` 中被环路锁定的那一个，
  **不是"相对 `fNco0` 的残余频差"**。
  决定性实测（`dop = 800 Hz`，混叠量 +50 Hz）：`f0 ∈ {700, 800, 900}` 时 `freq` 末段中位数**都 ≈ +50 Hz**；
  若按"残余"解释应分别得到 +100 / 0 / −100 Hz。判据要求三个值都落在 +50±5 Hz。
- 因此"用 `f0 + median(freq)` 做第二遍本振初值"是**错的**。正确重建（当 T=4 ms 时）：
  `f_new = 250·round(f0/250) + median(freq)`（即"离 f0 最近的 250 Hz 整数倍 + 混叠量"）。
  `app/80-coldstart.js` 已按此修正。

## 牵入难度的真正驱动
不是 `f0` 的 ±50 Hz 误差，而是 **`|wrap_{±125}(f_dop)|`**：
- 固定 `dop = 2123 Hz`（混叠 +123 Hz）时，`f0 ∈ {2000, 2100, 2123, 2200, 2300}` **全部牵不入**；
- 而 panel 场景的 6 颗星混叠量都较小（0/50/0/…），所以 6/6 锁住属于**场景侥幸**，不能推广。

## 边界处的假锁（上层必须知道）
当 `|wrap| → 125 Hz` 时，每块相位推进 → π：
- **atan** 失锁（|d| ≈ π）；
- **Costas 会假锁**：相位误差每块在 ≈0 与 ≈π 之间跳，而 Costas 对 180° 不敏感 → `d ≈ 0`、`lockQual ≈ 1`
  → `locked = true`，但载波相位是错的（每历元翻 π）。
  所以**上层不能只看 `locked`**：`app/80` 现在额外统计 `st.pllPass2Count`（有多少颗是靠第二遍 Costas 补锁的），
  这类锁必须另行判据（例如比较相邻历元的相位增量是否一致）。

## 修法（下一轮候选，按代价排序）
1. **加 FLL（叉积鉴频器）**：用相邻 prompt 的叉积 `Q_k·I_{k−1} − I_k·Q_{k−1}` 直接测频差，无 ±1/2T 模糊
   且牵引范围宽（∝ 1/(2πT)），牵入后再交给 PLL——这是真实接收机的标准做法；
2. **拉长相干积分**：T=10 ms → 模糊降到 ±50 Hz（代价：多普勒容忍度下降、码相位漂移影响变大）；
3. **让 NCO 频率参与环路状态**：把频率积分器折算进块内本振频率（`fNcoEff`），可消除一部分块间模糊，
   但实测对抖动略有代价（`review/proto-pll2.js`），需配合 FLL 使用。
