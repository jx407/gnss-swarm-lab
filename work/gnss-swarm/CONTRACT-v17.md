# 契约增补 v17（2026-10-06）——§16.6 相位基准约定：**必须用"残余相位"喂 PLL**

## 结论（本轮最重要的架构修正）
`pllTrack` 的环路状态 `φ` 跟踪的是**调用方给的相位基准下的误差**。基准怎么选，决定了牵引难度：

| 基准 | 每块 φ 必须吸收的推进 | 后果（实测） |
|---|---|---|
| **绝对**（喂 θ_true(t) = 2πf·t） | `2π·f·T` ≈ 53 rad/块（GPS L1、f≈4200 Hz、T=4 ms） | 积分器要爬上 rad 级得几百上千块 → 实测牵入 5/6，Monte Carlo 真实锁定率仅 47.9%（标准增益）/63.3%（高增益） |
| **残余**（喂 θ_true(t) − 2π·f₀·t） | `2π·(f−f₀)·T` ≤ 1.26 rad/块（f₀ 来自捕获，误差 ≤50 Hz） | 几十块内牵入；实测 6/6，相位误差 0.088–0.626 rad |

**约定**：只要捕获给了 `f₀`，就应当把 `f₀` 当"标称载波"，让环路只跟踪残差。
`app/80-coldstart.js` 的细块生成已改成
`carrierPhaseRad = θ_true(t) − 2π·f₀·t`（物理等价，只是换相位基准；t 取细块的绝对时刻）。

## 对 `freq[]` 语义的影响（与 §16.5 一起看）
`freq[g] = Δφ/(2π·t)` 的含义**随基准走**：
- 绝对基准 → 混叠后的绝对多普勒（模糊步长 `1/T = 250 Hz`，见 §16.5）；
- **残余基准 → 相对 f₀ 的残余频差**（残差 ≤50 Hz，远小于 125 Hz 模糊边界，故无混叠问题）。
因此第二遍的本振重建公式也随之不同：
- 残余基准：`f_new = f₀ + median(freq末段)`（当前 `app/80` 用的就是这条）；
- 绝对基准：`f_new = 250·round(f₀/250) + median(freq末段)`（§16.5 那条）。
**换基准时必须同步检查这两处**，否则会像本轮早期那样把频差修反。

## 与增益调度的关系（§16.4）
残余基准下牵引本来就很轻，增益调度（pass1 高增益 + 按需 pass2）退化为**安全网**：
实测面板场景 6/6 全部由 pass1 直接锁定（`st.pllPass2Count = 0`），没有依赖 Costas 回退（也就没有假锁风险）。

## 与"±125 Hz 混叠"的关系
§16.5 的混叠是**绝对基准**下的现象（φ 要吸收整块推进，mod 2π 后 ∝ wrap₁₂₅(f)）。
改残余基准后，φ 只吸收残差，**混叠不再构成牵入障碍**；§16.5 记录的 FLL/长积分修法仍是
"若将来要做无先验 f₀ 的盲牵引"时的正确路线。
