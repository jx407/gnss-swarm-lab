# 契约增补 v4（2026-10-06）——多系统星座（GPS / Galileo / BeiDou-3 MEO）

阅读顺序：本文件 + `CONTRACT.md` §0 + `CONTRACT-v3.md`。**不得修改** `GNSS.allSats` / `satEcef` 等既有函数的行为。

## 10. `GNSS.MULTI_SYS` / `GNSS.multiconst`

目的：真实接收机同时使用多个 GNSS 系统，可见星从 ~8 颗变成 20+，几何与冗余随之改善。本模块只负责**几何**（卫星位置与系统标签），
系统间钟差（ISB）留给上层在伪距上去模拟（`sysBiasM` 字段仅为参考值）。

```js
GNSS.MULTI_SYS            // { G: {...}, E: {...}, C: {...} } 每系统参数元数据
GNSS.multiconst(tSec, systems) -> [ { sys, svn, prn, x, y, z } ]
```

- `sys`：`'G'`（GPS）/ `'E'`（Galileo）/ `'C'`（BeiDou-3 MEO / 归一化为圆轨道）。`prn`：`'G01'`…、`'E01'`…、`'C01'`…。
- `systems`：字符串数组，如 `['G']`、`['G','E','C']`；非数组或空 → 返回 `[]`；未知系统名忽略。
- **轨道参数（全部圆轨道 e=0，简化但量级正确）**：
  | sys | a (km) | i (°) | 轨道面 | 每面卫星 | RAAN | 面内纬度幅角 u |
  |---|---|---|---|---|---|---|
  | G | 26561.75 | 55 | 6 | 4 | 60°·k | 90°·j + 30°·k + 1.5°·(prn mod 4)，其中 prn = svn + 1 |
  （**2026-10-06 修正**：原写 `1.5°·(svn mod 4)` 与"必须与 `GNSS.allSats` 逐位一致"矛盾——既有星座用的是 `prn mod 4`；
   两个变体都按后者实现并通过兼容判据，因此以 `prn mod 4` 为准。）
  | E | 29599.8 | 56 | 3 | 8 | 120°·k | 45°·j + 15°·k |
  | C | 27906.1 | 55 | 3 | 8 | 120°·k + 60° | 45°·j + 15°·k + 20° |
  其中 `svn` 是该系统内的序号（0 起），`k`/`j` 由 `svn` 按「每面 4（G）或 8（E/C）颗」推导，`k = floor(svn / perPlane)`、`j = svn mod perPlane`。
- ECI→ECEF 与既有模块一致：ECEF 位置 = Rz(−Ωe·t)·(用上表 RAAN、u 的 ECI 位置)。
- **硬性兼容要求**：`multiconst(t, ['G'])` 必须与 `GNSS.allSats(t)` **逐位相同**（位置完全一致）。
- `sysBiasM`（元数据，供上层模拟）：`{ G: 0, E: 20, C: -35 }`（米，示意量级；真实 ISB 在几十纳秒级）。
- 纯函数、确定性、不修改入参、无 DOM/依赖/console/Math.random；非法输入不抛异常。

必须满足（`tests/test-multiconst.js`）：
1. `multiconst(t, ['G'])` 与 `GNSS.allSats(t)` 位置完全一致（≤1e-9 m，且数量 24）。
2. 每系统卫星数：G 24、E 24、C 24；三个系统合计 72；`prn` 标签唯一。
3. 各系统地心距 |r| = 对应 a（±1 m），纬度幅值 ≤ 倾角 + 0.01°。
4. 刚体性：同一系统内任意两颗卫星的距离在一个轨道周期内保持不变（≤1 m）——圆轨道同面/异面都应满足。
5. 不重合：全系统内任意两颗卫星距离 > 100 km（不同系统 a 不同，天然满足；同系统要有相位抖动避免退化）。
6. 可见性：上海 (31.2304°N, 121.4737°E, 50 m) t=0、掩膜 10° —— GPS-only 可见 ≤ 12 颗，三系统可见 ≥ 18 颗。
7. 几何改善：同一站点同一时刻，三系统的 PDOP 必须小于 GPS-only 的 PDOP（用 `GNSS.visible` + `GNSS.dop` 检验）。
8. 确定性、入参不被修改、非法 `systems`（null、字符串、空数组）返回 `[]` 或等价空结果且不抛异常。
