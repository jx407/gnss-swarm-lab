GNSS 蜂群工作台

这是一套可动手比较的 GNSS 实验，覆盖星座、捕获到跟踪的完整链路。
每页开头有一句话读法，先看那句再看图；需要推导与实测数字时，再展开页尾的「详细说明」。
比较结果时只动一个参数，避免把不同条件混在一起。

术语速查（PDOP / RAIM / HPL / C/N0 / NEES / chip / spc …，点开）
  • PDOP / GDOP / HDOP / VDOP：几何精度因子——卫星在天上分布越开越小；PDOP < 2 算好几何，> 6 表示卫星挤在一起。
  • RAIM：接收机自主完好性监测——用多余观测互相校验，找出坏星。
  • HPL / VPL：水平 / 垂向保护限——由几何与噪声推出来的误差置信上界（本页对照 40 m 水平告警限）。
  • nmr：归一化残差（残差 ÷ 它的标准差）——RAIM 用它挑最可疑的那颗星。
  • 杠杆：帽子矩阵对角元；越接近 1，这颗星出错越容易被解自己吸收、越难检出。
  • chip：C/A 码的一个码片；1 chip = 1/1.023 MHz ≈ 0.978 μs ≈ 293 m。
  • spc：samples per chip，每个码片采几个点；采样率高，码相位才分得细。
  • C/N0：载噪比，衡量信号强弱；越高表示噪声越小。
  • σ：噪声标准差。图上写「峰 10.7σ」＝峰高是噪声的 10.7 倍；定位页的 σ 是伪距噪声（米）。
  • RMS：均方根误差——本页所有「误差 … m」都是 RMS。
  • DRMS：二维径向 1σ 圆半径，散点图里的虚线圈就是它。
  • TTFF：Time To First Fix，首次定位用时。
  • NEES：归一化估计误差平方，检查滤波器有没有「过度自信」（理论值 3）。
  • Costas：对载波 180° 相位翻转不敏感的鉴相器；DLL / PLL：延迟锁定环 / 相位锁定环。
  • lag：相关函数的时延自变量（单位 chip）；历元：一个采样时刻（本页多为 1 ms 或 1 s）。
  • 伪距：由传播时间算出的"距离"测量，含接收机钟差与大气延迟。
  • PRN：卫星编号（也指它的 C/A 码）；G12 ＝ GPS 第 12 号。
  • 多普勒：相对运动引起的频率偏移；捕获时按多普勒格搜索。
  • 电离层：高空自由电子造成的信号延迟；单频用模型只能改掉 50–70%。
  • 最小二乘：让"观测 − 模型"残差平方和最小的解算方法。
  • 相干积分：把 1 ms 的相关值同相累加（本页 4 ms），越长噪声抑制越好。
  • 周跳：载波相位计数的跳变（整周跳变/失锁），Hatch 平滑必须检测它。
  • 相关器：把接收信号与本地复制码做相关的部件；早/迟门用于 DLL 测距。
  • Walker 星座：均匀铺开的星座构型；本页 24/6/2 ＝ 24 颗、6 个轨道面、每面 2 个相位。
  • MEO：中圆地球轨道（BeiDou-3 MEO 半长轴约 27906 km）。
  • 掩膜：仰角门限；低于它的卫星不参与解算。
  • 自相关 / 互相关：同一颗星自己码对齐得有多尖 / 两颗不同 PRN 长得有多像。
  • 旁瓣：相关峰两侧的次要峰；越小越不容易误判。
  • 信噪比：信号与噪声的功率比（dB）；数值越低信号越弱——捕获页拖到 −30 dB 以下能看到相关峰被噪声淹没。
  • 双频消电离层：用 L1/L2 组合消掉电离层，代价是噪声放大 2.978 倍。
  • 数据位翻转 / IQ：导航电文的 ±1 会让相位跳 π；Costas 环对它免疫，IQ 星座图看收敛。
  • 窄相关 / 早迟门：只用峰附近很窄的早、迟相关点做判别，抗多径。
  • 卡尔曼滤波：用"预测 + 观测更新"递推估计位置/速度，把逐历元的抖动压平。
  • 蒙特卡洛 / 分位数：用大量随机重复实验统计结果 / 排序后取分位（中位数＝50% 分位）。
  • 采样格点：DOP 曲线每隔 15 min 取一个时刻；格子越密，中位数越稳。
  • 抖动：同一量在不同历元之间的波动幅度（本页用 RMS 或标准差表示）。
  • Klobuchar / α 系数：广播电离层模型的 8 个参数；本页只用 α（振幅项）。
  • CelesTrak：公开的卫星根数（轨道参数）来源；页面用其 2026-10-05 快照。
  • 环路阶数：PLL/DLL 的积分器阶数；阶数越高越能跟匀速漂移，但更容易失稳。
  • max|d|：鉴相器输出的最大绝对相位误差（弧度），越小说明锁得越稳。
  • 双峰：DOP 在一天里出现两个低谷（卫星构型周期性变化所致）。
  • ISB：系统间偏差（inter-system bias）——不同星座之间的钟差偏差。
  • ACQ：捕获（acquisition），即"在二维面上找相关峰"这一步。
  • LS：最小二乘（least squares）的缩写，见上面「最小二乘」。

详细说明：平台机制 · 两级搜索 · 前端带宽 · 实测与勘误（点开）

为什么"精修"能到 18 m —— 以及为什么提高信噪比没用。本工程的中频信号和接收机复制码都是按采样格硬采样的 ±1 方波（每个 chip 内取值恒定），所以落在同一采样格内的所有码相位会让相关器看到逐样本完全相同的码序列 ⇒ 相关值逐位相同（真的是同一个浮点数）。峰顶因此是一段宽 W = 1 个采样格 的平台：

  • 4 采样/chip：W = 0.25 chip ≈ 73 m。取「首个最大」恒落在平台左边缘，误差 RMS ≈ W/√3 = 42 m；取平台中心才是无偏的，RMS = W/√12 ≈ 21 m。老版本面板写的「±37 m 下限」其实是平台半宽，不是 RMS。
  • 本场景下提高信噪比无效（正确说法是"已饱和"）：平台内是同一个浮点数，噪声不改变它——实测 −20 dB 与 60 dB 给出的估计逐位相同（判据 tests/test-finesearch.js 已锁死）。但它不是无条件的：多径/带限失配会打破"码序列恒等"（|a₂|=0.9 时两档差 25 m），信噪比低到约 −35 dB 起会跑错平台（判据：平台间余量最小时只到均值 −2.4σ）。"SNR 档看不出电离层交叉点"的真正原因在这里，不在 SNR 上限。
  • 粗值错了怎么办（幅度门）：平台内逐点相等，所以如果粗捕的码相位已经错了 ≥1 chip，窗里每个格点都是旁瓣/噪声、峰形照样长成"平台"，会静默给错答案——实测偏 3 chip、200 个噪声种子时"峰落窗边缘"只报警 20%。可靠的门是每样本幅度 ampPerSample（码对齐 ≈1，滑到旁瓣/噪声 ≈0.03）；低于 0.35 就退回旧精修并计数。它同时能抓住"本振多普勒给错"（给 0 而真值 1200 Hz 时相关塌掉）。
  • 两个量别混：平台宽（分辨率元）= 1 采样格 = c/fs，4/16/40 采样/chip 分别是 73.3 / 18.3 / 7.3 m；平台中心下限 = 平台宽/√12 = 21.2 / 5.3 / 2.1 m。老文案的「±37 m」是 4 采样/chip 的平台半宽（=73.3/2），不是 RMS。
  • 唯一杠杆是采样率：两级搜索 = 4 采样/chip 全码粗捕（±0.125 chip）→ 在 ±0.5 chip 窄窗内用 16/40 采样/chip 信号重做相关并取平台中心。分辨率 18.3 m / 7.3 m，而代价只有粗捕的 3%–9%（窄窗只扫 17/41 个格点，全码是 1023 格 × 41 个多普勒）。

实测（本机 JS 真实计算时间，6 颗星 × 8 历元，本页默认场景）： ADC 档 4 → 16 → 40 采样/chip 时，码相位 RMS 36.7 → 11.4 → 4.0 m， 逐历元原始定位 RMS 74.1 → 28.8 → 12.8 m（载波平滑后 46.1 → 10.7 → 9.7 m，卡尔曼后 39.7 → 8.9 → 8.2 m）， 而 TTFF 几乎没有变化（三次独立运行都在 2.4–3.1 s，差 ±12%；其中细修只占 8 / 60 / 380 ms）——粗捕的成本大头是那道 1023² 的循环相关，它跟采样率无关。 也就是说：在"采样率"这一维上，精度几乎是免费的，这正是真实接收机愿意用 16–40 倍过采样去做码相位的原因。
单次实现的方差（勘误）：上面「载波平滑 / 卡尔曼」两列是一次固定种子的结果（本页因此可复现），但换一组噪声种子会在 ±十几米范围内波动——独立复核里换种子后理想方波档反而更好。判据用的是 40 组独立噪声取均值（LS 84.3 → KF 40.5 m），所以别用单次实现给「哪一档更好」下结论。 （口径提醒：上面那行"码相位 RMS"是整条链路的逐历元 RMS，主要由末历元的 DLL 跟踪决定； 精修本身在首历元的 RMS 是 13.0 / 6.4 / 1.9 m，面板明细里分行标注。 另外跟踪单次的耗时随 ADC 档线性增长——树上的 1023² 全码相关与采样率无关，而 DLL 的相关长度随之翻倍。）

那个"台阶"其实有两个来源，其中一半是我自己实现的伪影。 上面"平台内逐点相等"的前提是复制码也按整数样本量化——相关值在一整格内逐位相同，把信号侧本来有的信息也遮住了。 真实接收机不这么干：前端带宽（2–8 MHz 的 IF 滤波）把方波磨成光滑码波形，码 NCO 又是分数延迟的。两者补齐后， 相关峰顶就从"平台"变成光滑丘，插值才真的有信息。本页面把这两件事都做成了可切换的档位：

  • 「前端带宽（IF 滤波）」：理想方波 / 8 / 4 / 2 MHz。带限档把理想 ±1 方波过一遍高斯低通 （σ = 0.13251·Rcode/BW —— 这个常数才对应**真正的 −3 dB 带宽**；平坦段仍严格 ±1，只把跳变抹成斜坡。原先写的 0.3748 差了 2√2 倍，等于把"4 MHz 档"做成了 1.41 MHz，已按实测全部改过）；同一档位下 fineSearch 会自动把复制码也换成分数延迟查表（replicaBwHz 默认跟随信号）， 并用 auto 估计器判断峰顶是平台还是光滑丘。
  • 实测（ADC 16 采样/chip、6 颗 × 8 历元）：首历元精修 RMS 6.35 → 4.74 / 2.53 / 2.67 m（理想 → 8 / 4 / 2 MHz）， 链路码相位 RMS 11.4 → 6.1 / 4.8 / 4.6 m，逐历元原始定位 RMS 28.8 → 22.4 / 22.1 / 21.8 m。 注意不是"越宽越好"：8 MHz 档反而最差（链路 6.1 m）——16 采样/chip 的奈奎斯特是 8.18 MHz， 最优点落在 ≈4 MHz（f_s/4）；而 4 采样/chip（奈奎斯特 2.05 MHz）下最优是 2 MHz，更宽的前端只会被混叠 （实测 4 spc 的 16 MHz 档 27.8 m vs 2 MHz 档 18.0 m）。结论：带宽要与采样率匹配（约 f_s/4 ~ f_s/2）且不得超过奈奎斯特。
  • 控制实验（防止我把伪影当物理）：理想方波信号 + 分数延迟复制码 = 22.06 / 5.69 m （4/16 采样/chip），正好卡在信息下限 W/√12 上 ⇒ 只换复制码并不能突破，因为信号侧格内信息真的是 0。 带限信号 + 分数延迟复制码在 16 采样/chip + 4 MHz 上到 1.16 m（0.22× 下限）⇒ 突破成立； 但同一带宽换到 4 采样/chip（奈奎斯特只有 2.05 MHz）就**回到下限**（21.84 m ≈ 21.15 m）—— 带宽被混叠掉，信号侧信息又变回≈0。所以本页面演示的是"采样率 + 前端带宽如何共同决定信息下限"。

诚实标注：那两个"退步"其实不是退化。带限档下 Hatch / 卡尔的数字看着更差（10.7 → 16.0 m、8.9 → 12.6 m），但 ds4.1 子代理独立复核（含逐历元手工复算）表明：「增长窗口」的载波平滑在数学上就是码误差的滑动平均，两档这段滑动平均的量级相同（≈3.2 m），只是方向不同；位置误差是它经高 DOP 几何投影的结果（本几何投影增益 ×1.9–4.4）。决定性证据：只换噪声种子，两档优劣就翻转（种子 +1000：带限 8.4 m 反而优于理想 16.4 m）。所以这两个数是单次实现的结果，其方差大于两档的真实差异 —— 要严谨比较必须多实现取均值（列为下一轮第一优先）。同一轮复核还证伪了两条候选根因：DLL 残余多普勒（带限档 S 曲线过零点对 Δf 全为 0.00 m）与载波速率偏差（实测 0.002–0.003 m/历元，不是 1 m/历元）。

读法：这是冷启动 → 跟踪态的完整链路。面板有两种历元间策略：「首历元捕获 + 跟踪环」（真实接收机流程）只在第 0 历元做 101 格二维捕获（多普勒步长 100 Hz；这就是 TTFF，只计捕获耗时、不含首次定位解算），之后每个历元只做 2 组窄相关交给二阶 DLL，单次耗时比重新捕获便宜 6–16×（4 采样/chip 档约 45×——跟踪的相关长度随 ADC 档线性增长，而粗捕的成本大头是与采样率无关的 1023² 全码相关）；「每历元独立捕获 + 平均」是常见的"想当然"做法，每历元都重做一次全搜索。「历元间隔」滑块决定历元之间卫星跑多远：100 ms × 800 m/s 视向速度 ≈ 79 m ≈ 0.27 chip。把间隔拖到 0，两种策略都会贴到采样率决定的信息下限上：4 采样/chip 时 ≈21 m（平台宽 73 m 的平台中心），16 采样/chip 精修后 ≈5.3 m——注意提高信噪比并不能跨过这条线（下面「码相位精修采样率」段落有完整推导）；一旦有间隔，"独立捕获 + 平均"会把不同时刻的码相位当成同一个值平均，产生斜率·(N−1)/2 的结构性滞后（N=8、0.27 chip/历元 → 约 0.95 chip ≈ 280 m，而且 N 越大越差），跟踪环则把匀速滞后压到十几米——这就是接收机必须"先捕获、后跟踪"的原因。勾上「跟踪态加 8 维卡尔曼滤波」后，逐历元的伪距会再过一个 8 维 CV 卡尔曼（状态 = 位置 + 钟差 + 速度 + 钟漂，过程噪声按 σa = 0.5 m/s² 离散化）：曲线上那条绿色虚线就是滤波输出，本页当前场景实测逐历元 RMS 从 28.8 m 压到 8.9 m（3.2×），抖动从 10–39 m 收敛到 3–9 m。它不会修掉"独立捕获 + 平均"的结构性滞后（那种偏差不是噪声，对照模式下滤波后仍有 106 m），这也说明"先跟踪、再滤波"两个环节各管一件事。整毫秒模糊度用粗略位置（±15 km）与粗略钟差先验解开，这也正是接收机需要大致位置/时间的原因。

「信号信噪比」档要注意一个**反直觉结果**：从 −20 dB 提到 −8 dB，码相位 RMS 仍停在 ~20–28 m——因为误差已被 4 采样/chip 的平台宽（1 个采样格 = 0.25 chip ≈ 73 m，半宽 ±37 m）压住，信噪比不是有效杠杆。要再降必须提高采样率：平台宽 4/16/40 采样/chip = 73.3/18.3/7.3 m，平台中心估计的信息下限（＝平台宽/√12）= 21.2/5.3/2.1 m（Node 判据实测）。同理，电离层在 ×20 强扰动时（L1 斜距延迟 51 m）引起的十几米位置偏差**淹没在量化噪声里**，所以冷启动档看不出"模型 vs 双频"的交叉点——那个交叉点只在低噪声链路（定位面板 σ≤0.5 m）才显形。

这些数是怎么算出来的（点开）
  • 星座几何：可切「仅 GPS（24 颗）」/「+Galileo（48）」/「+BeiDou（72）」三档——三套系统都是解析圆轨道（GPS a = 26561.75 km、i = 55°，Galileo a = 29599.8 km、i = 56°，BeiDou-3 MEO a = 27906.1 km、i = 55°），轨道面升交点随地球自转以 −Ωe·t 西漂；GPS 单系统的位置与早期版本逐位一致。实测同一时刻可见星 7 → 21 颗、PDOP 2.81 → 1.06。接收机位置用 WGS-84。DOP 来自观测矩阵 G = [−u, 1] 的 (GᵀG)⁻¹，HDOP/VDOP 是把位置协方差旋转到当地 ENU 后取对角。
  • 真实星座：切到「真实 GPS」后换成 2026-10-05 抓取的 32 颗在轨 GPS 平均根数（CelesTrak gp.php?GROUP=gps-ops），用简化开普勒传播：牛顿迭代解 E − e·sinE = M、真近点角 ν = 2·atan2(√(1+e)·sin(E/2), √(1−e)·cos(E/2))，轨道面旋转 Rz(Ω)·Rx(i)·Rz(ω) 到惯性系，再用 GMST 反旋到地固系（ECEF = Rz(−θ)·ECI，θ 按 280.46061837° + 360.98564736629°·(JD − 2451545) 由统一参考时刻 T0 = 2026-10-05T22:32:31.853Z 起算）。32 颗元素历元跨度 18.62 天，本模块不做 SGP4 / J2 长期项：与「加 J2 长期项」的独立对照实测（review/probe-j2-error.js），新鲜 28 颗（外推龄 ≤2 天）中位差 4.2 km、最大 22 km，最老的 PRN21（18.62 天）151 km —— 所以这一档只保证几何结构可信。
  • C/A 码：G1/G2 两个 10 级 LFSR（1+x³+x¹⁰ 与 1+x²+x³+x⁶+x⁸+x⁹+x¹⁰），G2 按 IS-GPS-200 抽头表做异或选择，chip = G1 ⊕ G2，周期 1023，码率 1.023 Mchip/s，1 chip ≈ 293 m。
  • 捕获：4 ms 中频信号按 41 个多普勒格混频（乘 e^(−j2πft)），对码相位做循环相关；相干积分 4 ms 相当于约 36 dB 处理增益，再在胜出的多普勒行精修到 1 个采样点。
  • 定位与检核：对 [x, y, z, c·dt] 做线性化最小二乘（Householder QR）；定位面板在同一批数据上跑两种估计量——等权与高程加权（σ(el)² = σz² + (σh/sin el)²，低仰角自动降权，加权 DOP 用 (GᵀW̃G)⁻¹）。RAIM 用帽子矩阵对角元把残差归一化，超过阈值就剔除一颗粗差卫星后重解，下拉里给出每颗星的杠杆（越接近 1，这颗星的粗差越容易被解自己吸收、越难检出）。
  • 冷启动全链：逐颗生成 4 ms 中频信号（多普勒取自卫星径向速度、码相位取自几何距离+接收机钟差）→ 41 个多普勒格的二维捕获 → 抛物插值把码相位精修到亚采样 → 用粗略位置/钟差先验解开整毫秒模糊度 → 最小二乘得到首次定位。单历元快照的首历元码相位精修 RMS 实测 6.35 m（理想方波前端）／2.53 m（4 MHz 带限前端），所以首次定位在几十米量级；真实接收机靠更高采样率/插值、成形滤波与跟踪环（DLL/PLL）把码相位精度再提升 1–2 个数量级。
  • 导航滤波（8 维 CV 卡尔曼）：跟踪态逐历元的定位解仍然抖（6 颗星、PDOP≈2.8 时 43–219 m），再挂一层卡尔曼就能压平——状态 `[x,y,z,clk,vx,vy,vz,clkRate]`，预测用匀速模型（位置-速度块 dt³/3、dt²/2、dt 离散化过程噪声），量测是伪距 `ρ=|s−p|+clk`（`H=[−u,1,0,0,0,0]`、`R=σ_pr²I`），更新 `K=PHᵀ(HPHᵀ+R)⁻¹`、`P←(I−KH)P` 后强制对称。本页当前场景实测逐历元 RMS 28.8 m → 8.9 m（3.2×）；Node 判据里 40 组独立噪声的实测是 LS 84.3 m → KF 40.5 m（2.08×）、动态 5 m/s 下 2.15×，并且通过一致性体检：NEES 2.78（理论 3.0）、95% 置信椭球覆盖率 96.5%（理论 95%）—— 只比 RMS 的判据会被"把过程噪声调小、过度自信"骗过，NEES 不会。
  • 误差量级：−30 dB 时 4 ms 相干积分的理论峰仅约 5.7σ，而 折叠后 ≈4.2 万个等效噪声格（原始搜索面 4092×41）的最大噪声约 4.6σ，所以那是「边缘检测」；真实接收机靠多历元累加或多普勒辅助把它拉回来。城市多径会让伪距多出一段反射路径长度（按几何衰减）。误差预算面板把大气也算进来：天顶几米、5° 低仰角可达几十米（随太阳活动/时段/湿度变化；本页当前场景实测天顶 ≈7 m、5° ≈42 m），但所有卫星共同的那部分会被接收机钟差吸收，真正影响定位的是各方向延迟的不一致。
